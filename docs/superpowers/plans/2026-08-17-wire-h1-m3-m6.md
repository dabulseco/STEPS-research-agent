# Wire H1 / M3 / M6 Into `app.py` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Attach the three already-implemented tools (H1 `PubMedSearchTool`, M3 `CitationResolverTool`, M6 `LocalKnowledgeBaseTool`) from `tools.py` to the right CrewAI agents in `app.py`, then update the status and roadmap docs to reflect the new state.

**Architecture:** Add three one-line imports near the existing `tools.py`-adjacent imports, then add `tools=[...]` arguments to the three relevant `Agent(...)` constructions (Knowledge Researcher in `step2_initial_research`, Web Researcher in `step4_web_research`, Writer in `step5_write_output`). For the Writer, the agent is constructed once and reused across both the single-pass and section-by-section paths, so attaching tools there covers both. Update each agent's task description with a short, explicit instruction telling the local model when to call the tool — local-model tool selection is brittle without prompt scaffolding.

**Tech Stack:** Python 3.11+, Streamlit, CrewAI, Pydantic v2, Ollama. No new dependencies. All three tools already exist in `tools.py` with module-level singleton instances (`local_kb_tool`, `pubmed_search_tool`, `citation_resolver_tool`).

## Global Constraints

- The three tools already exist in `tools.py` with module-level singletons ready for `tools=[...]`:
  - `local_kb_tool` (M6) — wraps `DocumentStore.query_multi`; reads `st.session_state.session_id` and `embed_model`.
  - `pubmed_search_tool` (H1) — has `args_schema=PubMedSearchInput`; throttled via `_EUtilsState`; reads no session state (only env vars).
  - `citation_resolver_tool` (M3) — has `args_schema=CitationResolverInput`; throttled via `_EUtilsState`; reads no session state.
- `app.py` line 1064 = `step2_initial_research`. `app.py` line 1196 = `step4_web_research`. `app.py` line 1430 = `step5_write_output`. The Writer agent is constructed at line 1471 and is reused for both single-pass and sectional writing paths.
- All session_state keys used by `local_kb_tool` (`session_id`, `embed_model`, `rag_enabled`) are already initialised at `app.py:101–106`. No new session_state initialisation is needed.
- `st.session_state.rag_enabled` defaults to `True`. `local_kb_tool` returns `[]` when this is `False` — that means attaching it to the Knowledge Researcher is safe; it becomes a no-op when the user disables RAG.
- No new tests are added in this plan — the tools are not yet covered by unit tests, and adding them is a separate piece of work (out of scope). We rely on syntax-check + import-check + manual smoke check at the end.
